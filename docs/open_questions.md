# Open questions

Doubts about codes, formulas, sources and terms of use. Work continues on everything else and nothing is guessed: this is what is missing, what blocks what, and in which phase it will be resolved.

## Open

1. **Terms of use of the Portale Offerte open data**. Before redistributing the data, the licence indicated on the `ilportaleofferte.it` Open Data page must be verified: the page does not state it (checked on 21/10/2026) and it concerns both the offers XML and the "Prezzi storici" CSV of the indexes used for the PUN. It blocks phase 6 (service to third parties), not the ETL. A third-party source states CC BY 4.0, but it is not an official source: to be confirmed with ARERA / Acquirente Unico.
2. **URL and schedule of the parameters CSV**. The XML has an official URL (given by the user, used as the CLI default), the CSV does not: for now the local file is loaded. The publication frequency and the exact reference date are also needed. Without them, `just etl-scarica` loads the offers but not the parameters. (The Open Data page also publishes a dated URL for the parameters: see "Resolved".)
3. **`TIPO_DISPACCIAMENTO = 03`** (12 variable offers, `data_fine` 2026 or a sentinel). Track v5.0 does not define the code: it is either legacy or a seller typo. A decision is needed on whether to ignore it or map it to "other" in the calculation.
4. **BTA mapping** `_b1`…`_b6` → customer power/use and **units of measure of the parameters** in the CSV (absent from the file): the official documents of the parameter collection are needed. If they cannot be found, ask the user before adding the metadata table (phase B: the table does not exist yet, so it does not stay empty and unused).
5. **"Other" codes** (`IDX_PREZZO_ENERGIA=99`, `TIPO_DISPACCIAMENTO=99`, `MODALITA_PAGAMENTO=99`…): the track allows them but the real value is in a free-text field. How to handle them in the calculation (phase 4) must be decided: probably `non_calcolabile` with a reason, never an invented cost.
6. **Fixed offers with an index and the mixed offer** (phase 4): 16 offers with `tipo_offerta=01` still have an `IDX_PREZZO_ENERGIA` and the only `04` offer has `TIPO_PREZZO` on the intervals. Should they be treated as indexed? To be clarified before calculating their cost.
7. **Discounts and promotions** (phase 4): 968 offers have `Sconto/*` in `extra_json`. Phase A does not include them; if the user wants them in the comparison, an official rule is needed (the Portale Offerte applies them to the annual spend).
8. **GME terms of use for the PUN**. The `mercatoelettrico.org` site is protected by terms of use to be expressly accepted, with a disclaimer forbidding non-permitted uses of data and information: phase 3 does not use the GME but the "Prezzi storici" CSV of the Portale Offerte. The GME API is needed only if the **daily** PUN is required (it needs credentials provided by the user): before using it, the Terms of Use and Disclaimer must be read in full and what they allow for a service to third parties must be noted here.
9. **Which series the monthly "PUN (€/kWh)" in the Prezzi storici file is** (phase 4). The file publishes one value per month without saying how it is weighted: arithmetic mean of the daily PUNs, or the PUN Index GME, which the TIDE defines as the mean of the MGP zonal prices **weighted by the purchased quantities**? The values match third-party sources that cite the Portale Offerte, but how to resolve `IDX_PREZZO_ENERGIA` for an indexed offer must be confirmed on the track and with the user before calculating a cost.
10. **Stability of the Prezzi storici file URL**. The CSV sits in a `resources/cms/documents/` folder with an opaque name (`0c916785….csv`) and a monthly `Last-Modified` (07/10/2026 with data up to September 2026). It is not a dated URL: if the Portale replaces it, the download fails. The Open Data page remains the reference; for now the URL is a constant (`etl/pun.py`) and can be overridden with `--url`.
11. **Official Portale Offerte methodology for the total cost** (phase B, out of scope until the user asks): it must be found and cited in the code.
12. **VAT-number–seller-name mapping**: the offers track and the current model identify the seller by VAT number, but do not provide a reliable commercial registry. Before adding a `fornitore` table and populating it with the best-known sellers, an official source, an update date and a policy for mergers, name changes and unrecognized VAT numbers are needed; no guessed or unverified names are inserted.

## Resolved

- **Geographic zone codes**: `ZoneOfferta/REGIONE`, `PROVINCIA`, `COMUNE` are ISTAT codes (the track calls them "Elenco Codici Istat": region 2 digits, province 3, comune 6). `cerca_offerte` accepts the official region/province name or the code for `regione`/`provincia` and keeps `comune` a 6-digit code; the tables come from the ISTAT "Elenco dei comuni italiani" (source and URL in `offerte/zone.py`). The track reads the absence of `ZoneOfferta` as "whole national territory", but the tool still treats it as "does not match", as documented in the contract.

- **Track decodings**: from the official document "Funzionamento e Specifiche del Processo di Trasmissione Offerte Mercato Retail" v5.0 (Acquirente Unico, 15/12/2025), section "7 Formato e tracciato delle Offerte". 82 entries loaded into `codifica` from `etl/codifiche.py` (source and URL in the module). It includes the frequency in the description of `IDX_PREZZO_ENERGIA`, because the same index has different codes for quarterly/bi-monthly/monthly.
- **Date format** `gg/mm/aaaa_hh:mm:ss`: normalized to ISO 8601 with the `Europe/Rome` time zone (track, section `ValiditaOfferta`).
- **`DURATA = -1`**: from the track it means indefinite duration; stored as a string, with no interpretation.
- **Match between the published XML and track v5.0**: verified on real data (`docs/xml_validation.md`): zero unknown paths. The only name differences from the PDF table: `TipoPrezzo/TIPOLOGIA_FASCE` (plural) and `Dispacciamento/VALORE_DISP`; the parser uses the real names.
- **Representation of fixed-price offers**: documented in `docs/xml_validation.md` §9 (components `macroarea 04`/`02` in €/kWh, band only if the price depends on bands, index absent in 630 out of 646).
- **XML open-data download URL**: given by the user (`.../offerteML/AAAA_MM/PO_Offerte_E_MLIBERO_AAAAMMGG.xml`), used as the default by `python -m etl scarica`.
- **Dated URL of the parameters CSV**: the Open Data page also links `.../opendata/csv/parametriML/AAAA_MM/PO_Parametri_Mercato_Libero_E_AAAAMMGG.csv` (seen on 21/10/2026, updated on the same day as the offers). The date in the filename remains the reference. Wiring the download into `etl scarica` is a separate task: for now the CSV is passed with `--parametri`.
- **"Prezzi storici" file of the Portale Offerte as the source of the monthly PUN**: `;`-separated CSV in cp1252, columns `AnnoMese` (`AAAAMM`) and `PUN (€/kWh)`, one value per month since 2020; unit declared in the header and converted to €/MWh. Stored series: `PUN_MENSILE` (`etl/pun.py`). Verified on real data: 81 months, 2020-01 → 2026-09, August 2022 = 543.15 €/MWh (peak).
